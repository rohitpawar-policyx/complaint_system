Now implement the complete ADMIN PANEL.

==================================================
ADMIN ACCESS
==================================================

Every admin page must:

1. Verify authenticated session.
2. Verify the user's role/permissions server-side.
3. Reject normal users.
4. Never trust role information from GET/POST.
5. Never allow privilege escalation.

Use the shared authorization/middleware system.

Do not duplicate authorization logic unnecessarily.

The authenticated admin ID is the performed_by value.


==================================================
STATUS CHANGES
==================================================

When admin changes complaint status:

1. Verify authorization.
2. Load current complaint.
3. Validate new status.
4. Update complaint.
5. Create complaint_history record.
6. Store old status.
7. Store new status.
8. Store performed_by.
9. Store timestamp/description.

Use a transaction.


==================================================
ASSIGNMENT HISTORY
==================================================

When complaint is assigned/reassigned:

Store:

- complaint_id
- previous assignee
- new assignee
- performed_by
- action
- description
- timestamp

Create history automatically.

Never allow frontend to directly create history records.
